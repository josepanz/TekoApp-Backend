# Fase 0010 — Propinas

**Implementada 2026-08-28.** Backlog documentado en
`TekoApp-Frontend-Mobile/openspec/decisions.md`, sección "Backlog — features grandes pedidas
2026-08-08", ítem 2 ("Propinas: entidad separada relacionada a Payment (nunca fusionada al
monto), NO entra en el cálculo de comisión, 3 modos, opcional/obligatoria según parámetro/país").

## Diseño

- **`Tips`**: entidad separada, `paymentId` único (una propina por pago). `userId`/
  `professionalId` denormalizados desde el `Payment` para queries directas. `mode` (`PERCENTAGE`/
  `FIXED`/`FREE`) + `percentage` (solo si `PERCENTAGE`) + `amount` (siempre poblado — si es
  `PERCENTAGE` se calcula server-side desde `Payment.amount`, si es `FIXED`/`FREE` lo manda el
  cliente directo). La distinción `FIXED` vs `FREE` es de UI/analítica (preset vs. monto libre
  tipeado), no cambia el cálculo backend.
- **Nunca toca el pago**: `fee-calculator.service.ts` (`calculatePlatformFee`/
  `calculateProviderFee`) no recibe ni conoce el monto de la propina — se calcula y persiste por
  completo fuera del flujo de `PaymentApiService.createPayment`. `Payment.totalAmount`/`fee`/`tax`/
  `platformFee` quedan sin ningún cambio.
- **`TipConfig`**: parametrizable (`isEnabled`/`isMandatory`/`suggestedPercentages`/
  `allowFreeAmount`), resuelto por país con el mismo criterio ya usado para
  `LegalDocumentVersions` (`countryId: null` = default global — Paraguay-only por ahora, sin país
  por Service/User todavía). Sin fila cargada → fallback seguro en código (mismo patrón que
  `FeeCalculatorService` con `PlatformCommissionConfig` faltante), no se sembró ninguna fila por
  migración/seed (mismo criterio que `PlatformCommissionConfig`, que tampoco tiene seed).
- **`isMandatory` es informativo**: el frontend debería mostrar el paso de propina como no
  salteable cuando es `true`, pero el backend NUNCA bloquea la creación/finalización de un pago
  por falta de propina — no hay ningún dominio real que obligue esto a nivel de cobro (no hay
  integración real de proveedor de pago, ver hallazgo abajo).

## Endpoints nuevos

- `GET /tips/config` — config activa (JWT, cualquier usuario logueado).
- `POST /payments/:id/tip` — crear propina (solo el cliente dueño del pago, una vez, solo si
  `PAID`/`COMPLETED`).
- `GET /payments/:id/tip` — obtener la propina de un pago (sin chequeo de propiedad adicional,
  mismo criterio ya existente en `PaymentApiService.getPaymentById` — ver "Fuera de alcance").
- `GET /payments`/`GET /payments/:id` (ya existentes) ahora incluyen `tip` anidado — se agregó al
  `include` compartido (`serviceRefInclude` en `payment-db.service.ts`), sin duplicar queries.

## Hallazgo real durante la investigación (no en el backlog original)

El pago en este backend es **simulado/interno** — no hay integración real con Stripe (`transactionId`
es un `uuidv4()` generado localmente, `processStripeWebhook` solo interpreta payloads entrantes
simulados, nunca se crea un `PaymentIntent` real). Esto significa que no hay ninguna restricción
técnica de "misma transacción de cobro" que obligue a que la propina viaje junto al pago del
servicio — la decisión de mantenerla como una entidad 100% separada fue de diseño de dominio, no
forzada por el proveedor de pago.

## Fuera de alcance (deliberado)

- **UI de configuración de `TipConfig`** (staff): no se construyó — mismo criterio que otros
  modelos de config nuevos en fases anteriores (empiezan de solo lectura/backend, la UI de admin
  se agrega después si hace falta).
- **Montos fijos preestablecidos** (`mode=FIXED` con opciones tipo "Gs. 5.000 / 10.000 / 20.000"):
  no existe un campo de config para esto — solo `suggestedPercentages`. El frontend (Mobile/Web)
  solo ofrece `PERCENTAGE` (chips) y `FREE` (monto libre); `FIXED` existe en el dominio pero sin
  UI que lo dispare todavía.
- **`GET /payments/:id/tip` sin ownership check**: se mantuvo consistente con el mismo criterio ya
  existente en `PaymentApiService.getPaymentById` (cualquier usuario logueado puede consultar un
  pago por su referenceId) — no se amplió esa laxitud, tampoco se la corrigió (fuera del alcance
  de esta fase).
